# Agent instructions — Suzhou gardens collection

本文件约束 `suzhou-gardens/` 下所有园林。进入具体园林后，继续阅读其 `AGENTS.md`、`CODEX_TASK.md` 和相关规格。

## 每园独立

1. 每座园林使用一个独立子目录：`liuyuan/`、`wangshiyuan/`、`zhuozhengyuan/`、`shizilin/`、`canglangting/`。
2. 园林专属代码、资产、测试、截图、任务书、依赖和构建配置均放在对应园林目录内。本层只保留系列索引与共同约束。
3. 用户于 2026-10-04 明确要求完成本仓库指定的五座苏州园林，并沿用此前选择的 ChatGPT Site 交付。留园保留已交付的 M2，其余四园按各自任务书与规格独立实现、验证和交付。各园工作目录仍严格分开。
4. 各园独立安装、运行、构建和测试。不在本层或仓库根目录创建应用、npm workspace、统一场景注册表或跨园依赖。
5. 不为未来复用提前抽象共享引擎、编辑器或资产库。后续若需跨园改动，先由明确任务规定范围。
6. 不把留园的场景、真实名称、石峰或任务书复制到其他园林后改标题充数。每园后续分别制定规格与验收依据。

## 已授权的统一入口

用户于2026-10-04进一步要求用一个ChatGPT Site作为入口。`portal/` 为独立静态导航目录，允许存放自身页面、真实园景缩略图、检查和发布配置；只链接五园既有Site，不在系列层初始化应用，不建立共享场景或跨园运行时依赖。其实现遵循 `portal/AGENTS.md`。

## 工作纪律

- 阅读并保留已有文档；脚手架不得清空目录或覆盖设计规格。
- 默认只修改当前园林目录。更新系列索引必须与实际状态一致，不顺带改动兄弟目录。
- 不提交凭据、私有照片或未授权素材；不擅自部署、启用付费服务或指定整个仓库的许可证。
- 实现状态、截图和测试结果必须有真实证据；文档或占位目录的存在不等于应用可运行。

当前任务入口：各园自己的 `CODEX_TASK.md`；实际交付状态见 [系列索引](README.md)。
