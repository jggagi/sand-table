# 《掌上留园》设计与实现规格

版本：v0.1，2026-10-03。状态：设计规格，不代表应用已实现。

本文件定义完整首作的方向；当前执行范围以 `../CODEX_TASK.md` 为准。第一轮为 M1，屋顶抬升等后续需求不得混入首轮。

## 1. 产品定位

一件能在浏览器里把玩的苏州园林微缩作品。默认从斜上方观察，用户旋转、拉近，并通过少量观景点读懂不同空间的关系。

核心体验：**水面舒展，廊院层叠，奇石独立。**

不以测绘精度或内容数量作为第一目标。先做好同一底座上的一组构图，不做全园等比例重建、城市地图、第一人称游戏或通用园林编辑器。

成功不是“程序生成了白墙黑瓦”，而是水、建筑、山石与遮挡被有意识地安排，四个视角都值得停留，能辨认出留园的创作依据。

## 2. 真实依据与艺术化边界

公开介绍对留园中部山水、东部庭院及曲廊联系有明确描述，也说明中部池南主体建筑、冠云峰与配峰、浣云沼等关系。来源见 [R1](REFERENCES.md#r1-留园空间依据)。本作品只提取这些关系，不声明具备测绘资料。

| 必须保留的设计约束 | 允许的艺术化处理 |
| --- | --- |
| 中部池景与东部石峰庭院保持分区，冠云峰不进入中部大池 | 压缩两区之间的距离，省略重复建筑 |
| 池景较疏朗，廊院较紧凑，建筑不是对称环形排布 | 调整尺度以适配微缩可读性，局部树冠可降低 |
| 中部较厚重的山体与东部瘦高奇石有不同造型语言 | 省略无法确认的表面细节，用统一材质凝练表达 |
| 廊、墙、门窗形成真正的遮挡与可视开口 | 简化廊院组合，不假称真实游客路径 |
| 重点建筑与石峰具有单独设计的轮廓 | M1 可先占位，但必须标记，后续可替换 |

页面常驻或可直接打开的说明：

> 根据留园代表性空间提炼的艺术化微缩景观，非等比例全园复原。

不使用“真实全园导览”“数字孪生”“精确还原”等表述。观景点是针对作品设计的机位，不冒充实地拍摄位置。

## 3. 场景组成

### A. `central-water`：中部池景

主体是不规则水面、较厚重的山石地形、涵碧山房/明瑟楼的简化组合、辅助临水构件与少量树木。具体建筑关系以 R1 和后续多角度参考核对；M1 不编造细部。

制作重点：水面形成连续留白；建筑有开间和高低变化；岸线不可是一圈等距随机石头；植物不能遮住全部屋顶与池岸。中部山石用较宽厚的块面，不能复制冠云峰缩放后铺满岸边。

### B. `corridor-courts`：压缩廊院连接

包含转折回廊、至少一个小院、一段有真实开口的院墙及少量竹石。其作用是把两区连为一件作品，而不是一条孤立的连接线。

至少在 `corridor` 机位有明确的前景墙/柱、中景开口、后景景物三层关系。M1 可采用分段墙围出门洞；不能用黑色面片假装洞口。漏窗花样和更复杂构件在 M2 打磨。

### C. `guanyun-court`：东部石峰庭院

包含单独设计的冠云峰、简化配峰、独立的小水景和院落围合。冠云峰应是此区的视觉中心，旁边构件和树不能抢同等轮廓。

M1：瘦高、不对称、分段收放、适当负空间的明确占位形体。M2：根据参考调整轮廓，制作真实可透视的孔洞，避免甜甜圈或随机积木感。不可用表面贴黑色斑点冒充孔洞。

只给有依据的建筑/石峰挂真实名称。普通辅助亭、廊、树和无法确认的构件使用通用 ID，不虚构景点名。

### 坐标与构图基准

以下为作品参数建议，**不是实际尺寸或平面图**：Y 向上，X 正向为模型东侧，Z 负向为模型北侧；地面 Y=0，底座向下延伸。总占地可从约 32×24 模型单位起步，底座保持薄，不做悬浮断崖。

可先将中部安排在 X=-13 到 1 的范围，廊院在 X=0 到 6 附近，石峰庭院在 X=5 到 14 附近；区域允许衔接和重叠，边界不是裁切箱。根据四个机位调构图，比机械遵守初始坐标更重要。

首屏需同时看到大水面、屋顶节奏和冠云峰；主物体不要贴边。全园不做镜像对称，不让树冠成为实心绿色屋盖。

## 4. 美术语言

目标：精致实体沙盘感，不是写实扫描，也不是卡通积木。

| 元素 | 表现方向 | 避免 |
| --- | --- | --- |
| 背景与底座 | 暖中性背景、浅石底座、柔和接地阴影 | 宇宙背景、悬浮岛、厚重装饰底盘 |
| 建筑 | 暖白墙、深灰瓦、深褐木构；轻微边缘圆润 | 塑料白、夸张飞檐、所有建筑一个模板 |
| 山石 | 低饱和灰石与较暖厚重山体；轮廓有节奏 | 任意噪声、重复球体、整园同一块石头 |
| 植物 | 明确主干、分枝和疏密，少量姿态不同的树 | 等距球形树、随机散布遮住主景 |
| 水 | 克制的青绿、轻微明暗层次；M1 可静态 | 镜面金属水、强 Fresnel、复杂实时流体 |
| 光照 | 单一柔和主光加环境补光，能读出屋檐和庭院 | 浓雾、过曝泛光、强景深掩盖细节 |

材质统一比纹理分辨率优先。优先使用程序化颜色、粗糙度和简单几何，无需从网页抓纹理。重复瓦和栏杆按远近简化，先解决屋顶轮廓，再补单片瓦。

M1 使用固定光照和静态环境。M2 以后最多加入很轻的水纹与枝叶运动；必须能停止，截图模式下固定。默认不自动旋转模型，不自动播放音乐。

冠云峰和主体建筑是重点资产；宁可减少树和装饰，也不要用泛用替代物冒充最终成品。

## 5. 相机、观景点与状态

### 整体观察

使用正交相机，采用单个 Drei CameraControls 或等价的单一控制器；核对版本后实现，参考 R3。默认不允许翻到底座下，限制过近/过远缩放和目标漂移。M1 可禁用平移，把旋转与缩放做好。

正交画面的大小由 zoom/视锥决定，不靠改变相机距离。建议用稳定的 `verticalSpan` 或场景包围盒计算视口适配；横竖屏切换后重新计算可见范围，不使用只对一个屏幕有效的固定像素 zoom。

初始机位可以从 position=[32, 27, 36]、target=[0, 1, 0] 起调；数值是起点，不是验收标准。整个底座与主要树冠都应留有安全边距，不能只在宽屏里完整。

### 四个固定 ID

| ID / 名称 | 构图对象 | 建议展示文案 |
| --- | --- | --- |
| `overview` / 全园入掌 | 同一底座上的水、廊院与石峰 | 一边是舒展的水面，一边是层叠的庭院。 |
| `waterside` / 临水看楼 | 中部临水建筑与岸线，保留远景层次 | 建筑与树石错落，让水面成为画面的留白。 |
| `corridor` / 廊间一瞥 | 真实开口及其后方景物 | 从墙与廊之间，看见藏在后面的另一层空间。 |
| `guanyun` / 庭中观石 | 冠云峰、配峰和周边院落 | 把视线留给石峰的轮廓，与庭院之间的空隙。 |

这些文案是本作品的观察引导，不是新增园林史实。允许根据最终构图修改，不能描述画面里根本不存在的景物。

### 过渡规则

相机预设带 position、target、可见范围和关联区域；切换使用同一个控制器。用户拖动时立即中断预设过渡；快速多次点击以最新请求为准。不同动画不得同时直接写 camera transform。

手动观察之后，UI 应显示自由观察或取消预设高亮，不能假称仍在精确的固定机位。复位清除过渡，恢复 overview；M3 增加抬屋顶后，复位还要恢复屋顶与模式。遵守 reduced motion，必要时直接切换而不是过渡。

## 6. “看层次”模式（仅 M3）

通过按钮抬升少量指定屋顶，保留柱、墙、门窗和地面；目的是露出廊院组织，不是整座建筑爆炸分解。

屋顶对象使用 `roof-*` ID，保存不可变的初始局部变换。抬升幅度相对这些初始值计算，不能每次点击累加 Y 造成漂移。开关可中断、可反向；快速连点或连续切换 20 次后依然能准确恢复。

M1 只需把关键建筑的 roof/body 分组，保留实现余地，不写未使用的抬升系统。M3 不增加视线锥、热力图、路径算法或复杂教学平台。

## 7. UI 与可访问性

默认中文，canvas 是主体。标题、简短提示与观景按钮组成轻量界面；移动端将文案压缩或折叠，不能铺满屏幕挡住园林。

DOM 观景按钮可键盘访问、具有焦点样式和可理解名称，必要的文本不只存在于 canvas。鼠标/触摸操作提示简短，避免要求用户先读长篇说明。M3 可增加对齐场景的热点，但同一功能必须保留 DOM 入口。

初始化状态不伪造百分比；错误分辨 WebGL 不可用与场景/资源加载失败，提供可读反馈。没有静默白屏，没有为修复错误而无限刷新。

不依赖在线字体、图库热链或第三方运行时 API。首版不收集访问或交互数据。

## 8. 工程组织

选 React + TypeScript + Vite + Three.js + React Three Fiber + Drei，保持静态前端。版本和运行时要求根据官方文档核对后锁定，见 R2–R3；不要复制过时 API 或无条件安装 latest 组合。

建议结构（实现时创建，不代表现在已有）：

```text
suzhou-gardens/
  package.json
  package-lock.json
  index.html
  src/
    main.tsx
    App.tsx
    scene/
      GardenScene.tsx
      CameraRig.tsx
      regions/
      primitives/
    data/
      liuyuan.layout.ts
      liuyuan.views.ts
      liuyuan.content.ts
    ui/
    styles/
  public/
    assets/liuyuan/
  tests/
  docs/
```

保持少量清晰模块，可按实际实现调整。`primitives/` 只抽取真实重复构件，不先建立泛化平台。

数据至少表达：区域 ID、对象 ID、位置/旋转/比例、几何参数、样式 token、占位状态和可选来源 ID；观景点引用稳定区域/对象 ID，不能把数组下标当身份。初始配置用有类型的 TS 模块即可，不需要 JSON 编辑器或数据库。

后续替换 GLB 时保持对象 ID、局部原点、Y-up 方向和缩放约定；M1 不需要为不存在的模型创建空文件、远程 URL 或加载失败的占位链接。

## 9. 性能和确定性

优先控制场景复杂度，再加效果。复用重复材质和几何，柱/瓦/植被适合时使用实例化；不要每帧分配大对象或重建几何。静止时可按需渲染；存在相机阻尼或环境动画时必须正确请求后续帧，不能为了省电让过渡中途停住。

M1 使用确定性布局和固定种子。相机稳定与资源 ready 后提供真实的渲染就绪信号，便于自动化等待；该信号不能替代对非空画面和真实交互的检查。

初始优化参考预算：桌面普通视角约不超过 250 次 draw call、约 30 万可见三角形，DPR 不高于 2；超出时先检查是否来自不必要的瓦片/树叶。预算不是硬性通过标准，也不是已测性能。后续按设备测量调整，并以保住主轮廓为降级原则。

M4 再测试桌面流畅旋转、移动端尽量稳定 30 FPS、持续使用无明显资源增长等目标。软件渲染或触摸模拟不能代表真实手机 GPU、发热与手势体验。

## 10. 不在本项目首作范围

全园测绘、第一人称行走、碰撞/寻路、NPC、多人、自动生成所有园林、复杂天气/季节、照片重建、高斯泼溅、AI 导游、账号、后台、内容编辑器、跨项目框架以及自动商业部署。

未来可以扩展，但必须由新的明确任务驱动，不能作为“顺便完善”加入 M1。
