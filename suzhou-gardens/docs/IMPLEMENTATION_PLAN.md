# 实施计划与验收

创建于 2026-10-03。下列为待办路线，不是工作完成记录。当前仅授权实现 M1，详见 `../CODEX_TASK.md`。

## 里程碑

| 里程碑 | 目标 | 交付物 | 进入下一轮的依据 |
| --- | --- | --- | --- |
| M1 构图原型 | 三个关联片段与四个可操作机位 | 可运行网页、锁文件、基础测试、五张真实截图、报告 | 整体布局和交互已可观察，已知占位清楚 |
| M2 美术样板 | 从占位打磨成统一的模型语言 | 重点建筑、冠云峰、植物、水与材质，替换后的对照截图 | 四个角度有完整作品感，主要轮廓不依赖标题解释 |
| M3 交互完成 | 观景与结构解读可稳定使用 | 屋顶抬升、状态恢复、必要热点、可访问性和边界测试 | 连续操作、触摸、resize、reduced motion 都有验证 |

## M1 执行顺序

### M1.1 安全初始化

- [ ] 阅读当前文档，检查仓库后续是否出现新的上层约束或已有实现。
- [ ] 保留文档，在 `suzhou-gardens/` 建立 Vite + React + TypeScript 项目。
- [ ] 核对稳定依赖兼容性，记录 Node/npm 要求并提交锁文件。
- [ ] 提供 dev/build/preview/typecheck/test/test:e2e scripts；普通 test 为非 watch。
- [ ] 设置忽略规则：不提交 node_modules、dist、缓存、临时 trace/video、凭据和私有文件。

验收：应用基础页与 canvas 可以启动，初始化/失败状态可读，没有外部资源才能显示的硬依赖。

### M1.2 同一底座上的构图

- [ ] 建立确定性的布局、观景点和文案配置。
- [ ] 制作中部池景、廊院、东部石峰庭院三个区域；它们之间有真实可见的空间联系。
- [ ] 使用有意设计的建筑、石峰和植物占位，不是默认几何散落在平板上。
- [ ] 墙洞可透视；水面有留白；石峰和主体建筑不被植被完全遮住。
- [ ] roof/body 分组及对象 ID 稳定，为 M2/M3 留接口但不提前做相应功能。

验收：从整体及三个局部角度截图，都能判断比例、遮挡与疏密。构图不依赖精细贴图才成立。

### M1.3 相机与页面

- [ ] 正交旋转缩放、俯仰/缩放边界、四个预设、一键复位。
- [ ] 手动输入可打断过渡，连续请求以最后一次为准。
- [ ] 桌面和竖屏均能看全主体，resize 不把模型裁掉。
- [ ] 标题、提示和文案保持克制，按钮支持键盘与触摸。
- [ ] reduced motion、WebGL 失败反馈和艺术化说明。

验收：普通用户不用了解开发工具即可操作；页面不呈现假功能按钮，不需要登录。

### M1.4 验证与交付

- [ ] 实际运行安装、类型检查、构建和测试，记录退出结果。
- [ ] 浏览器确认真实 canvas 非空、有几何、有不同视角，而非只检查 DOM 按钮。
- [ ] 四张桌面固定机位截图及一张竖屏手机截图。
- [ ] `docs/reviews/m1/REPORT.md` 记录环境、命令、结果、占位项、限制和待反馈的构图问题。
- [ ] 更新 README 的状态和实际运行方法，保留设计规格与未来路线。

M1 不需要所有材质完成，也不需要真实手机性能测试通过；尚未验证的部分必须明确写出。

## M2 美术打磨

优先级依次为：整体构图修正、冠云峰轮廓、涵碧山房/明瑟楼组合轮廓、屋顶与窗廊、树姿与岸线，最后才是装饰与轻微环境运动。

- 对重点物体补充参考，不把网页照片直接变成可发布贴图。
- 替换程序化占位时保持稳定对象 ID 与相机目标，不要求重做 UI。
- 冠云峰的细孔和主要负空间需要真实可透视结构，不能黑色贴图冒充。
- 对照 M1 相同机位，不只挑一个新机位遮掩其他角度退步。
- 将来源记录与仍属艺术化估计的部分留在资产台账。

完成标准：作品形成统一的实体沙盘感；整体、临水、廊间、观石四个视角都成立；不能仅凭自动测试宣布美术验收通过。

## M3 交互与稳健性

实施可恢复的“看层次”屋顶抬升；必要时加入与 DOM 按钮一致的场景热点。验证连续切换 20 次、转场中拖动、快速连点、抬升过程中复位、横竖屏切换和 reduced motion。

屋顶从不可变原始姿态计算目标，不累加位移。切换模式不丢失对象与选中状态；离开页面或组件卸载时释放自有资源。

完成标准：没有漂移、残留动画、状态错乱与操作争抢，移动端可用，文本说明不挡主景。

## M4 性能与发布准备

选择并记录实际测试环境，而不是预先声明所有浏览器支持：至少一个桌面 Chromium 环境、Safari/iPad 或 iPhone 环境，以及一个 Android Chromium 环境。环境缺失要明确标注；模拟不替代真机。

测量启动到可交互时间、旋转时帧率和长时间操作后的资源趋势。固定网络、视口、DPR、浏览器和渲染器信息后再比较，不能用开发机一次结果推断所有设备。

降低开销优先移除高成本反射/后期、减少无意义瓦片与叶片、降低阴影和 DPR，最后才减少关键轮廓。

静态构建需支持部署到子路径；资源地址和相机深链接不得硬编码站点根路径。默认不自动启用 GitHub Pages 或其他服务，先交付部署文档，实际发布由后续明确任务决定。

## 验证矩阵

| 检查 | M1 必需 | 后续补充 |
| --- | --- | --- |
| 数据 | 唯一 ID、四个预设完整、引用有效、坐标和缩放范围合法 | 模型替换契约、来源 ID 校验 |
| 应用 | 可启动、可构建、类型检查、错误反馈 | 静态子路径部署、资源失败恢复 |
| 渲染 | 真实非空场景，预设截图具有不同构图 | 多浏览器、关键资产和光照回归 |
| 交互 | 切视角、手动操作、复位、缩放限制、resize | 抬升恢复、热区遮挡、触摸真机 |
| 性能 | 无明显逐帧重建与运行时错误，记录环境 | 真机帧率、加载与长时资源趋势 |
| 美术 | 疏密、留白、遮挡和独立轮廓可评价 | 统一模型感、四视角质量、资料核对 |

截图必须等几何/资源就绪且相机停止。自动测试可使用固定种子和静止环境；不得把测试数据换成伪造场景以通过检查。跨平台像素可能有差异，先保证可重复机位并人工看图，再决定是否采用像素阈值回归。
