# Agent instructions — suzhou-gardens/liuyuan

本文件约束 `suzhou-gardens/liuyuan/` 及其下所有应用、资产、测试和文档。先阅读上层 `../AGENTS.md` 与本文件，再阅读 `CODEX_TASK.md`、`docs/LIUYUAN_SPEC.md` 和 `docs/IMPLEMENTATION_PLAN.md`；查资料与模型时阅读 `docs/REFERENCES.md`。

## 固定决策

1. 首座是留园，不重新比较或改选网师园、拙政园。
2. 产品是艺术化、实体沙盘感的 Web 微缩景观，不是写实重建、开放世界或第一人称游戏。
3. 本轮范围由 `CODEX_TASK.md` 决定。原任务为 M1；用户随后授权 M2 艺术化打磨，已交付，见 `docs/reviews/m2/REPORT.md`。2026-10-04 五园任务保留本园 M2，不扩展 M3/M4。
4. 核心构图为中部池景、简化廊院、东部冠云峰庭院。保留疏密对比，不能把三块做成互不相关的展品，或挤成对称的通用中式庭院。
5. 压缩和省略必须承认是艺术化处理。不虚构测绘精度、真实游线、史实或已经获授权的资料。

## 修改边界

- 所有实现和依赖默认放在本子目录 `suzhou-gardens/liuyuan/`。未经新任务要求，不改动其他园林，也不在上层或仓库根目录创建应用、依赖或跨项目框架。
- 当前目录已有任务书；脚手架不得清空或覆盖这些文档。必要时在临时目录初始化，再有选择地移入文件。
- React + TypeScript + Vite + Three.js + React Three Fiber + Drei；选相互兼容的稳定版本，记录 Node/npm 要求并提交 npm 锁文件。不要默认采用 alpha、beta 或实验性 WebGPU 路线。
- M1 使用可重复生成的程序化几何，无需 Blender、付费资产、模型 API 或外部下载才能首次启动。
- 不添加后端、数据库、登录、AI 导游、遥测、广告、第三方追踪或用户内容上传。不自动开通付费服务或发布站点。
- 不提交密钥、个人路径、访问令牌、私有照片或未经许可的素材。公开网页仅作为参考，不等于资产授权。

## 场景与代码

- 布局、观景点、UI 文案分离为带类型的数据；使用稳定语义 ID，后续替换 GLB 不应重写 UI。
- 参数化构件只服务本场景。不要提前做通用园林生成器、编辑器、复杂插件或 ECS。
- 几何、材质和实例布局初始化一次；随机分布使用固定种子，不在逐帧循环或 React render 中重建场景。
- 正交相机的缩放必须调整 zoom 或视锥，而不是仅改变距离。只有一个相机控制系统可以修改相机。
- 用户拖动应中断相机过渡；连续点击应由最后一次请求生效。适配 resize、竖屏和 reduced motion。
- 开口要能看穿，冠云峰要有有意设计的轮廓；禁止用黑色贴面冒充洞，或用一根默认圆柱充当最终石峰。
- 尊重资源生命周期：复用材质和几何，卸载后清理自有资源，不误释放仍在共享的资源。
- 文案与说明使用中文；代码标识符使用清晰英文。对占位形体和未知细节如实标记。

## 验证与交付

- 必须交付可运行页面，不以长篇解释、架构空壳、静态概念图或只有首页的页面代替。
- 实现后实际运行类型检查、构建、单元测试与浏览器检查，记录完整命令及结果。未执行、失败和受环境限制的项分别报告，不能写成通过。
- 浏览器截图必须来自实际应用。M1 截图需要固定视口、固定种子、相机稳定并完成渲染；不得使用假截图、空 canvas、mock 场景或仅用 DOM 按钮通过测试。
- 无浏览器或 WebGL 环境时仍交付可运行代码和能执行的检查，明确缺少视觉验证；不要伪造结果或因此放弃整个任务。
- 不以大量 `skip`、屏蔽错误或删除验收项制造全绿结果。若兼容性确实阻塞，记录原因和最小替代方案。

- 完成当前里程碑后停止扩 scope。保留可继续打磨的源码，而非只交压缩构建产物。
